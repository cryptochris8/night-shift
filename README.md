# NIGHT SHIFT

One hospital night. Three people. The same three hours.

**Play it:** [night-shift-game.netlify.app](https://night-shift-game.netlify.app). Headphones recommended; contains flickering light.

NIGHT SHIFT is a browser-based psychological horror / mystery prototype. You are not one protagonist: you move between **John** (a patient waiting to be seen), **Susie** (a nurse called in to cover), **Paul** (environmental services, who knows the building better than anyone) and the wing's **CCTV** feeds, while a single shared timeline runs from 10:45 PM to 1:45 AM. What one of them sees, another may not. The cameras may disagree with both.

Everything you see and hear is generated by code at runtime: no imported models, images or fonts, and no audio files but one. Geometry is three.js primitives, textures are drawn on canvases, sound is synthesised with the Web Audio API. The exception is the title screen's briefing, read by an ElevenLabs narrator.

## What you're doing

You get two jobs, and the night keeps running whether you are watching or not.

1. **Keep everyone accounted for.** Switch between John, Susie, Paul and the cameras whenever you like, but the clock runs for all of them at once. When the ring around someone's portrait (bottom right) starts to fill, something is wrong where they are: go to them. Leave them alone too long and they go missing.
2. **Work out what is really happening.** Every night is secretly one of four kinds: *grounded* (real-world causes), *psychological*, *supernatural*, or *mixed*, and the game never says which. Nobody's account is reliable. Medication, fear and fatigue bend what each person perceives, and the cameras can disagree with the people standing in the hall. You piece it together from documents, camera footage and what each of them witnesses.

Choices change the night along the way. John can tell Susie about the lights, or not. Susie can believe him, or give him something to help him rest. When the power fails, Paul chooses which zones the generator keeps powered, and whether to reset the west wing breaker. Susie has to pick between an alarm in Bay 2 and a call light in Bay 3, and decide whether to check the elevator when it chimes.

## How a night ends

| Ending | How you get it |
|---|---|
| **Someone Missing** | Anyone is lost before 1:45 AM. This overrides everything else. |
| **Something Came Through** | Everyone makes it, the night really was supernatural (or mixed), and you found at least three clues that prove it. |
| **A Rational Explanation** | Everyone makes it and at least three clues point to ordinary causes. The ending explains the night, then leaves you one detail it can't. |
| **Morning Comes** | Everyone makes it, and nothing is explained. |

The title screen carries a short version of this as a narrated briefing. Wide screens show it beside the menu; on phones it sits under **Briefing** in the menu. The first time the title has sound (after your first click, tap or key press), a narrator reads it aloud while the text follows the voice line by line. Once you have heard it through, or pressed **Stop**, it no longer starts by itself. **Listen** replays it any time, and Settings → **Title narration** turns the automatic reading back on.

## Run it

```bash
npm install
npm run dev        # http://127.0.0.1:5173
```

Production build and preview:

```bash
npm run build
npm run preview    # http://127.0.0.1:4173
```

Requires a modern desktop browser with WebGL 2 (Chrome, Edge, Firefox). Headphones recommended. Contains flickering light.

The live copy is a Netlify deploy, with its build settings in `netlify.toml`. From a checkout linked to the site, `netlify deploy --prod` builds the game and publishes it.

|---|---|---|
| Move | W A S D / arrows | Left stick / d-pad |
| Look | Mouse | Right stick |
| Walk faster | Shift | — |
| Interact | E / Enter | A |

| CCTV: next / previous camera | ] [ or . , | RB / LB |
| Flashlight (Paul) | F | X |
| Pause | Esc | Start |

Touch devices get an on-screen stick and buttons.

**First night:** a short walkthrough teaches the controls as you play. You look around, walk, buy something from the vending machine, then switch into Susie and back. A few tips follow later in the night (the first time you take Paul or the cameras, and the first time someone else is in trouble). It turns itself off once finished. Pause → Skip tutorial skips it, and Settings → Tutorial brings it back.

## Night Seed

Every shift is generated from a **Night Seed** (shown on the title and ending screens, e.g. `NS-7F3A-21`). The seed decides which anomalies happen, where the clues are, how each character perceives shared events, and what the hospital is actually hiding that night. Enter a seed on the title screen to replay a specific night. The game never tells you which kind of night you got.

## Settings

Master / music / effects volume, motion effects, film grain, reduced flicker, subtitles, **Title narration** (the briefing reads itself aloud until you have heard it through), mouse sensitivity, invert Y, quality, **Tutorial** (the first-night walkthrough), and **Difficulty** (Easy / Normal / Hard — scales how fast characters get into trouble while you are not watching them).

## Development

```bash
npm run typecheck  # tsc --noEmit (strict)
npm test           # Vitest: rng, clock, state, layout invariants, nav, collision, visibility, endings, UI input, tutorial, briefing
npm run build      # typecheck + production bundle in dist/
```

Headless QA tools (Playwright Chromium with software WebGL; each starts its own no-HMR dev server from `vite.qa.config.ts`, with its own dependency cache so it never disturbs a running `npm run dev`):

| Command | What it checks |
|---|---|
| `node tools/smoke.mjs` | Title → intro → every perspective → outage → generator → crisis → ending, with screenshots in `tools/shots/` |
| `node tools/night.mjs --scale 60` | A whole night at 60× speed with perspective switching and auto-answered choices; `--smart` follows danger warnings like an attentive player |
| `node tools/shots.mjs` | Photographs fixed camera poses (`--power generator`, `--pose name,view,x,z,lx,ly,lz`) |
| `node tools/mobile.mjs` | Restart flow and phone layout with touch emulation |
| `node tools/audiolevel.mjs` | Synthesized output level per sound state (silence / clipping) |
| `node tools/doctest.mjs` | Documents and choices respond to the keyboard |
| `node tools/tutorial.mjs` | Plays the first-night walkthrough with real key presses: every step, the console hint, the tips, the 22:59 clock hold, Skip from the pause menu, the setting switching itself off, phone layouts |
| `node tools/briefing.mjs` | The title briefing: layout at five desktop sizes, silence until the first gesture, the narration starting by itself, the text following the voice, the ambience ducking under it, Listen/Stop and keyboard reach, the setting switching itself off, New Shift fading it out, the phone sheet |
| `node tools/probe.mjs "<js>" --play` | Evaluate an expression inside a running game (`s` = services) |

Architecture: `src/core` (types, contracts, store/bus, clock, seeded RNG, input) · `src/world` (floor plan, procedural geometry, props, room visibility) · `src/render` (textures, lighting, post-processing, cinematics) · `src/characters` (first-person controller, procedural figures, navigation) · `src/audio` (synthesized ambience and effects) · `src/cctv` · `src/interact` · `src/ui` · `src/events` + `src/story` (the director: shared timeline, anomalies, perception, choices, endings). `CONTRACT.md` documents the module boundaries and the story spine.

### The narration

The briefing's words live in `src/ui/briefing.script.ts`. That one file feeds both the title screen and the recording. After changing a line, re-record it:

```bash
ELEVENLABS_API_KEY=... node tools/narration.mjs            # re-records only the lines that changed
ELEVENLABS_API_KEY=... node tools/narration.mjs --verify   # also transcribes every line and diffs it against the script
```

The tool records one clip per line, then trims, joins and masters them to -17 LUFS. It writes `src/assets/briefing.mp3` and the cue sheet `src/ui/briefing.cues.ts` that the highlight follows. Takes are cached in `tools/narration/cache` (git-ignored), and `--dry` rebuilds from that cache without the API. `npm test` fails if a line was edited without being re-recorded.

Debug hooks live on `window.__NS` (`setTime(minutes)`, `switchView(view)`, `fire(eventId)`, `state()`); add `#debug=1` to the URL for an overlay with the timeline, danger levels and upcoming events, and `#seed=NS-XXX-XXX` to play a specific night.
